# ГГКИТ Карьера ЧР

Кадровый портал ГБПОУ «Грозненский государственный колледж информационных технологий» и организаций-партнёров
Чеченской Республики. Соединяет **соискателей** (студентов, выпускников), **работодателей** и **администрацию колледжа**:
от регистрации до отклика на вакансию и ответа работодателя.

Проект вырос из статичного демонстрационного сайта (HTML/CSS/JS с данными прямо в браузере). Сохранены фирменный стиль,
логотип и тексты интерфейса; вся логика, данные и безопасность перенесены на сервер.

## Возможности

- **Главная**: поиск, рекомендуемые и свежие вакансии, статистика *из базы данных*, партнёры, «как это работает», преимущества для студентов и работодателей, блок «О нас», подвал с контактами.
- **Каталог вакансий** (`/vacancies`): поиск по должности, работодателю и городу; фильтры по категории, типу занятости, опыту, зарплате; сортировка по дате и зарплате; пагинация; активные/закрытые; вкладки «ГГКИТ / партнёры»; карточки и таблица. Фильтры работают совместно, состояние хранится в URL.
- **Страница вакансии** (`/vacancies/<id>`): у каждой вакансии свой адрес, работает прямой заход. Описание, обязанности, требования, условия, адрес со ссылкой на карту, контакты, данные об организации, отклик.
- **Партнёры** (`/partners`, `/partners/<id>`): логотипы, описания, города, сферы, контакты, открытые вакансии, статус проверки.
- **Кабинет соискателя** (`/cabinet`): профиль, подтверждение статуса студента/выпускника, резюме (до 5), документы (PDF/DOC/DOCX/PNG/JPG), история откликов с отзывом, избранное, уведомления, настройки (email, пароль, удаление аккаунта).
- **Кабинет работодателя** (`/employer`): карточка и логотип организации, заявка на проверку, создание/изменение/удаление/публикация/закрытие вакансий, отклики с профилем и резюме кандидата, смена статусов, внутренние комментарии, статистика.
- **Панель администратора** (`/admin`): пользователи (блокировка, роли, временные пароли), модерация вакансий, организации и каталог партнёров, заявки студентов и закрытый реестр, все отклики, журнал действий, редактирование контента сайта.
- **Отклики**: резюме + письмо; статусы *Отправлен → На рассмотрении → Просмотрен → Приглашение на собеседование → Принят / Отклонён*, а также *Отозван*; защита от дубликатов; уведомления обеим сторонам.

## Требования и быстрый старт

Нужен **Node.js 22.13 или новее** (используется встроенный `node:sqlite`). **Внешние npm-зависимости не требуются** —
`npm install` не нужен, но команда безвредна.

```bash
# 1. Настройка окружения
cp .env.example .env            # Windows (cmd): copy .env.example .env

# 2. Создание базы данных (миграции)
npm run migrate

# 3. Первый администратор
ADMIN_EMAIL=admin@example.ru npm run create-admin     # Windows (cmd): set ADMIN_EMAIL=admin@example.ru && npm run create-admin
#   команда выведет временный пароль — при первом входе его нужно сменить

# 4. Запуск
npm start                        # или npm run dev — с автоперезапуском
```

Сайт откроется на <http://localhost:3000>.

### Демо-данные для разработки

```bash
npm run seed
```

Загружает 6 вакансий и 6 партнёров из исходной версии сайта (помечены `is_demo`), организацию «ГГКИТ», демо-аккаунты
(пароли случайные и **выводятся один раз**; чтобы задать один известный пароль локально, на чистой базе выполните
`SEED_PASSWORD=Demo12345 npm run seed`) и **вымышленные** записи реестра студентов `TEST-STU-001`, `TEST-STU-002`,
`TEST-GRAD-001`, `TEST-GRAD-002`. В production команда отказывается работать.

Контакты в подвале сидер берёт из данных подразделения колледжа в исходном проекте — проверьте их в админке («Контент»).

## Настройка (.env)

Все параметры описаны в [.env.example](.env.example). Ключевые:

| Переменная | Назначение |
|---|---|
| `PORT`, `HOST` | адрес и порт сервера |
| `BASE_URL` | публичный адрес сайта (ссылки в письмах) |
| `DATABASE_PATH`, `UPLOAD_DIR` | файл SQLite и каталог загрузок — вне `public/` |
| `COOKIE_SECURE` | `true` в production (только HTTPS) |
| `TRUST_PROXY` | `true`, если сервер стоит за обратным прокси |
| `MAIL_PROVIDER` | `none` / `console` / `webhook` |
| `MAX_UPLOAD_MB` | лимит размера документа |

Файл `.env` в репозиторий не попадает (`.gitignore`). Секретных ключей в приложении нет: сессии — случайные токены, в базе хранится только их хеш.

## Роли и первый вход

| Роль | Как появляется | Доступ |
|---|---|---|
| Соискатель | регистрация `/register` | `/cabinet` |
| Работодатель | регистрация `/register?role=employer` (создаётся организация) | `/employer` |
| Администратор | **только** `npm run create-admin` или другой администратор | `/admin` |

Роль определяется на сервере по сессии; значения из браузера не учитываются. Администратор не может сам себя заблокировать,
сменить себе роль или оставить портал без администраторов. Пароль, выданный администратором (создание администратора,
сброс), — временный: до его смены доступна только страница настроек.

## Структура проекта

```
server/
  index.js, app.js        запуск, диспетчер запросов, сессии, CSRF, лимиты, раздача статики
  config.js, db.js        настройки (.env), доступ к SQLite и миграции
  migrate.js, seed.js, create-admin.js   команды
  routes/                 auth, account, public, candidate, applications, employer, admin
  lib/                    security (scrypt), validate, uploads, router, mailer, registry, dto, queries, ...
migrations/001_init.sql   схема базы данных
public/                   фронтенд (единственная папка, доступная из браузера)
  *.html                  тонкие оболочки страниц
  css/style.css           исходные стили (сохранены) · css/app.css — новые компоненты
  js/                     api.js, ui.js, layout.js, components.js, vacancyForm.js, appDetail.js, pages/*.js
tests/                    автотесты (node:test) · tests/e2e — браузерный сценарий (Playwright, необязательно)
docs/API.md               описание REST API
```

Почему без Express и сторонних пакетов: в среде разработки не было доступа к npm-реестру, а встроенных средств Node 22
(`node:http`, `node:sqlite`, `node:crypto`) достаточно. Роутер (`server/lib/router.js`) намеренно маленький;
при желании его заменяют на Express — обработчики не зависят от конкретного фреймворка.

## База данных

SQLite (WAL), миграции — файлы `migrations/NNN_*.sql`, применяются по порядку командой `npm run migrate` (и автоматически при старте).
Новая миграция — новый файл с большим номером; применённые не редактируются.

Основные таблицы: `users`, `roles`, `sessions`, `password_resets`, `candidate_profiles`, `employer_profiles`, `organizations`,
`categories`, `vacancies`, `applications`, `application_status_history`, `application_comments`, `resumes`, `documents`,
`saved_vacancies`, `notifications`, `student_registry`, `verification_requests`, `verification_history`,
`organization_verification_requests`, `activity_logs`, `site_content`.

Важные решения:
- уникальный индекс `applications(vacancy_id, candidate_id) WHERE status <> 'withdrawn'` — один активный отклик, после отзыва можно откликнуться снова;
- в отклике хранится **копия резюме** на момент отправки;
- внешние ключи включены (`PRAGMA foreign_keys = ON`), значения статусов ограничены `CHECK`;
- даты — UTC, формат ISO 8601.

## Безопасность

- Пароли: **scrypt** (N=32768, r=8, p=1), индивидуальная соль, сравнение за постоянное время; блокировка входа на 15 минут после 5 неудач; одинаковый ответ для неверного пароля и несуществующего email.
- Сессии: случайный токен в cookie `HttpOnly; SameSite=Lax` (+`Secure` в production); в базе — только SHA-256 токена; завершение остальных сессий при смене пароля.
- CSRF: токен сессии в заголовке `X-CSRF-Token` для всех изменяющих запросов авторизованного пользователя + проверка `Origin` + обязательный `Content-Type: application/json`/`multipart`.
- Доступ: роли проверяются на сервере в каждом защищённом маршруте; данные чужих организаций/пользователей возвращают `404`.
- XSS: динамический текст вставляется только через `textContent`; CSP `script-src 'self'; style-src 'self'` (без inline-кода); ссылки в интерфейсе проверяются.
- SQL: только параметризованные запросы; спецсимволы `LIKE` экранируются; поиск без учёта регистра для кириллицы.
- Загрузки: список расширений, проверка **содержимого** (сигнатуры), лимиты размера и количества, случайные имена, хранение вне `public/`, выдача с `Content-Disposition: attachment`, `nosniff` и `sandbox`; SVG не принимается.
- Лимиты запросов (скользящее окно по IP): вход, регистрация, восстановление пароля, загрузки, заявки.
- Ошибки: клиент получает общее сообщение, подробности — только в консоли сервера.
- Журнал действий (аудит) без паролей и токенов; просмотр реестра и чужих документов администратором тоже записывается.
- Реестр студентов — только на сервере; доступен лишь администраторам; кандидату результат сверки не показывается, работодателю передаётся лишь факт подтверждения.

## Развёртывание в production

1. Сервер с Node.js ≥ 22.13, домен и TLS-сертификат (Let's Encrypt).
2. Код без `.env` и `data/`; создайте `.env` из `.env.example`:
   `NODE_ENV=production`, `COOKIE_SECURE=true`, `TRUST_PROXY=true`, `BASE_URL=https://ваш-домен`, `HOST=127.0.0.1`.
3. `npm run migrate`, затем `ADMIN_EMAIL=… npm run create-admin`. **Не запускайте `npm run seed`.**
4. Запуск как службы (пример `systemd`):

```ini
[Service]
WorkingDirectory=/opt/ggkit-career
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server/index.js
Restart=always
User=ggkit
Environment=NODE_ENV=production
```

5. Обратный прокси (пример nginx) с TLS; сохраните заголовок `Host` — по нему проверяется `Origin`:

```nginx
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $remote_addr;
  client_max_body_size 6m;
}
```

6. Резервные копии: файл базы (`sqlite3 data/ggkit.sqlite ".backup backup.sqlite"` при работающем сервере) и каталог `uploads/`.
7. Запускайте **один процесс**: лимитер запросов хранится в памяти процесса, а SQLite рассчитана на один сервер.

## Тесты

```bash
npm test          # 78 автотестов бэкенда и статики (node:test), ~4 с
npm run check     # проверка синтаксиса всех JS-файлов
npm run test:e2e  # сквозной тест в браузере (нужен Playwright: npm i --no-save playwright && npx playwright install chromium)
```

Автотесты покрывают: регистрацию и вход, хеширование, блокировки, CSRF, лимиты, восстановление пароля, права ролей на каждый
защищённый маршрут, изоляцию данных, вакансии и модерацию, поиск/фильтры/сортировку/пагинацию (включая кириллицу и спецсимволы),
отклики и статусы, загрузку файлов (подмена расширения, размер, обход путей), проверку студентов, панель администратора,
журнал, раздачу статики и защиту от выхода за каталог `public/`. Браузерный сценарий проходит основные пути всех ролей,
следит за ошибками консоли и CSP и проверяет отсутствие горизонтальной прокрутки на 375 и 820 px.

## Подключение внешних сервисов

Ничего не имитируется: пока сервис не настроен, интерфейс прямо сообщает об этом.

| Что | Состояние | Что нужно |
|---|---|---|
| **Отправка писем** (сброс пароля) | `MAIL_PROVIDER=none`: письма не отправляются, в интерфейсе — честное сообщение; администратор выдаёт временный пароль | выбрать провайдер: `webhook` (URL + токен HTTP-API вашего почтового сервиса) или добавить SMTP в `server/lib/mailer.js` |
| **Подтверждение email / SMS** | не реализовано (нет провайдера) | почтовый/SMS-провайдер |
| **Официальная база студентов ГГКИТ** | недоступна; используется закрытая таблица `student_registry` с тестовыми записями | реализовать `findByNumber()` в `server/lib/registry.js` (API/БД колледжа) или загрузить данные в таблицу |
| **Платежи, карты** | не реализовано | — |

## Известные ограничения

- Email пользователя **не подтверждается** письмом; смена email защищена паролем.
- Лимиты запросов и блокировки хранятся в памяти (после перезапуска сбрасываются; несколько процессов не поддерживаются).
- Один процесс/одна база SQLite — для нагрузки порядка сотен одновременных пользователей достаточно, для большего потребуется PostgreSQL.
- Уведомления появляются при открытии страницы или переходе между разделами (без push и realtime).
- Просмотры вакансии считаются при каждой загрузке страницы (без дедупликации).
- Внешние файлы (карты, шрифты, CDN) не используются; ссылка «на карте» ведёт на Яндекс Карты по адресу.
- Контактные данные колледжа в подвале заданы из данных исходного проекта и требуют проверки.
